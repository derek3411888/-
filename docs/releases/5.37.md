# Payload 5.37 / Launcher 5.49

An explicit manual or scheduled fresh launch now takes precedence over an older owned workflow. The launcher verifies the previous main's identity, requests its normal exit, waits for recording finalization and owned helper shutdown, and acquires installation ownership before updating any files. Duplicate starters remain serialized. Unverifiable ownership or an unfinished recording blocks replacement instead of force-killing unrelated programs.

After safe takeover, abandoned maintenance and final-synthesis transactions are archived and removed from active state. A prior failure no longer becomes the next fresh run's pending transaction. Settings, completed-server history, official maintenance notices and notification deduplication remain intact.

Internal restart, resume and next-server handoffs retain their existing progress and protection limits. A newer STOP or PAUSE command still supersedes the older fresh-launch request, including across launcher relocation.

Launcher and Payload are rebuilt together. Website and API sources are unchanged; the server bundle remains 1.0.88. Background regression, isolated current/legacy takeover, restart handoff, compilation and package consistency are release checks. Six production-dependent native tests remain deferred while active games are protected. Publication is not proof of installation or live gameplay acceptance on either device.
