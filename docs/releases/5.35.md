# Payload 5.35 / Launcher 5.47

Caps Lock-only protection: the main RUN workflow periodically detects an enabled Caps Lock state and turns it off. Synthesis, OKWW and LRMC also check at their existing input boundaries. Already-off state does not emit input; a held key waits for release. The main PAUSE/STOP and interactive-desktop gates are checked before correction, with a fresh key-state check at the final input boundary. Failed correction is read back and rate limited.

The four AHK entrypoints no longer restore a previously-enabled Caps Lock state while sending their normal keys. No permanent keyboard remapping or other lock-key setting is introduced.

No changes to synthesis decisions/counts, restart limits, task continuation, server completion, game configuration, website or API behavior. The unchanged server bundle remains version 1.0.88. Both Launcher and Payload are rebuilt together so future updates retain the Caps Lock guard.

Release validation uses the established Background profile while production remains running. Six stopped-production native tests remain deferred, not passed. Publication and package hashes do not establish that an already-running device has loaded this change; the existing flow is not restarted as part of publication.
